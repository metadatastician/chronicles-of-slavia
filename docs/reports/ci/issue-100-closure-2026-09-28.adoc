== Foundational follow-through (the loop-breaker)

Dependabot rewrites `uses:` and never updates `actions.lock`; the lock is
platform-enforced; therefore *every* routine grouped actions bump desyncs this
repo's CI. Measured on this repo: #112 killed three workflows hours after
#111 had revived them, and auto-merge completed anyway because the lock gates
are not in the required set. Mitigations landed here:

* `.github/dependabot.yml`: `open-pull-requests-limit: 0` for
  `github-actions` — GitHub's security-only switch (security PRs still flow;
  routine desync-producing bumps stop). Revisit condition recorded inline.
* `scripts/update-actions-lock.sh` vendored byte-identical from
  `hyperpolymath/standards@a2ff696ab8f5e0b38823ad3b5cdff72772093c6e` — the
  gates' remediation text referenced it, but the file did not exist in this
  repo.

Fed back upstream (see the issue thread for links): hypatia#869 (compile
break), standards#994 class notes (SonarQube token class; Hypatia consumer
pinning; lock mechanism confirmation), rsr-template-repo (template carries the
same latent desync for non-codeql actions; dead `gh.io/actions-lockfile` doc
URL in the lock header).
