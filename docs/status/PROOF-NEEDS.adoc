== Applicability decisions

=== SNIF

Not applicable on the present tracked-source horizon: the repository contains
no Erlang, Elixir, C/C++, or header source and no NIF implementation pattern.
If a BEAM native boundary is introduced, it must use the estate SNIF isolation
path; absence today is not a permanent exemption.

=== ABI/FFI

The estate template-applicability policy requires capability-gated modules to
exist if and only if the project declares the capability. The project currently
has no `.machine_readable/rsr-profile.a2ml`, while its metadata calls the
interface tree unused template scaffolding. Resolve this before authoring more
generic ABI proof material:

. remove the vestigial ABI/FFI/generated/proof scaffolding and declare the game
  as zero-FFI; or
. declare `abi`/`ffi`, replace every placeholder with a real contract, use the
  unified Hexadeca API, generate the boundary, wire it, and prove conformance.

Merely keeping files that typecheck is not a capability implementation.

== Proof acceptance checklist

A future item may move from `Needed` to `Confirmed` only when all apply:

* the theorem names a Slavia or retained interface invariant;
* the implementation-to-model correspondence is explicit;
* the authoritative prover/gate runs and rejects a planted broken proof;
* no configured trust escape hatch is present;
* the proof is wired to CI on the implementation paths it constrains;
* the status record cites the exact module, checker, revision, and horizon.

Compilation of unrelated scaffolding does not satisfy this checklist.
